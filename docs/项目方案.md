# SDD SKILL 与内容方案

版本：1.1  
更新日期：2026-10-01  
配套要求：[内容与写作规范](内容与写作规范.md)

## 1. 目标

当前维护三类产物：

1. 一个能够支持完整开发闭环的 SDD SKILL。
2. 一套 SDD 知识分享内容，包括单文件《SDD 学习实战笔记》、`01–09` 系列文章、模板、工作底稿和演示大纲。
3. 一套供当前文稿引用的 SDD 学习实战笔记 V2。
4. 一套音频优先的讲解视频流程，先审阅短样片，再决定是否处理完整录音。

主要读者是入行数年的初级工程师，以及愿意深入理解软件设计与 AI 协作的本科生和研究生。这套流程作为个人实践版本介绍，不宣称是统一的行业标准。

## 2. 工作流

SDD 使用七个可回退的步骤：

1. 明确目标、非目标和成功标准。
2. 核实当前实现与已有约束。
3. 设计必要的职责、边界、契约和失败语义。
4. 裁决影响当前增量的关键问题。
5. 从现状与目标的差距推导最小可验证任务。
6. 在授权范围内实施，并处理新证据带来的变化。
7. 用实际证据验收，同步受影响规范并刷新当前事实。

文档深度随风险调整。局部且易回退的变化可以使用简短记录；涉及公开契约、持久化、状态所有权或复杂失败路径时，补充相应设计。

## 4. 交付边界

- SKILL 可在用户授权后调查、修改代码并运行验证。
- 内容制作任务只产出文字和图示说明，不创建练习项目。
- 讲解视频可使用用户提供的录音作为内部素材；原始录音、转写稿、字幕、工程与模型缓存保留在 Git 忽略目录。
- 音频粗剪只生成候选时间线和审阅清单。工作流先生成带字幕 cue 与时间范围的 Markdown 页面大纲，再通过 AI 内容复审与人工逐项决定循环；内容问题处理完且大纲获批后，用户才在 Shotcut 定稿音轨。
- 演示生成后另行检查同步与画面质量；口播问题回内容复审，视觉或页面时间线问题回演示修改。音轨有变化时重新转写、校对、对齐字幕并更新页面映射。
- 样片通过人工审阅前，不处理完整录音，也不沿用剪辑前的时间戳。
- 分析或评审请求默认只读，不隐含实施授权。
- 原始笔记、历史聊天、旧版本发布稿和内部项目细节不进入 Git。
- 不以测试计划、文件存在或 AI 自评代替实际完成证据。

## 5. 验收

- SKILL 通过结构校验，入口、引用和 UI 元数据一致。
- V2 方法资料的原有正文、标题和文件名保持不变；单文件总览按当前内容方案维护。
- 内容目录中的相对链接能够访问，模板占位链接不作为缺失文件处理。
- 所有新案例均标明虚构性质，并通过隐私与可识别性检查。
- 外部系统结果未知时保持未知，不承诺无法由接口保证的投递或执行语义。
- 内容中的公开来源链接能够访问，并直接支持相邻说明。
- 视频样片包含原时间码转写、静音粗剪工程和 A/B/C 审阅清单；最终网页以定稿音轨的播放时间驱动画面，并可在 Shotcut 中复核导出。
- 页面大纲、问题和补录使用稳定 ID；每轮复审针对最新大纲，人工处理完全部问题并批准后才进入音轨定稿。
- 工作流状态只保存阶段、文件路径/哈希、依赖关系和审批结果；样片质量回路与内容审核回路各自按问题类型返回。
