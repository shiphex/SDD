## 2. 开始一个中等以上变化

- [ ] 请求类型和授权范围明确。
- [ ] 当前问题、Goal、Non-goal 和 SC 足以判断完成。
- [ ] 关键当前事实已核实，假设与未知项已标记。
- [ ] 系统边界、状态 owner 和生命周期 owner 唯一且清楚。
- [ ] 成功主链与关键失败分支都可说明。
- [ ] 状态、事件、Guard 和触发权限一致。
- [ ] 公开契约说明输入、输出、状态效果和领域失败。
- [ ] 外部副作用的超时、幂等和结果未知已经裁决。
- [ ] 重大取舍有 ADR、验证和 Escape Hatch。
- [ ] SC、架构规则、Failure ID 和测试能够对应。
- [ ] Current Facts 与 Target 的 Gap 已明确。
- [ ] 当前 Task 只有一个主要可验证结果。

## 3. Task 动手前

- [ ] References 指向具体 Spec 条目，不只写文件名。
- [ ] Preconditions 解释为什么现在可以开始。
- [ ] Allowed scope 按职责区域定义，必要接缝有理由。
- [ ] Must 只包含 Goal 必需事实。
- [ ] Must not 防住最可能的范围扩张和边界破坏。
- [ ] Verify 在编码前写明。
- [ ] 高风险任务已完成 Preflight 和要求的人工评审。
- [ ] 未决问题只阻塞真正依赖它的工作。

## 4. 实现中出现偏差

```text
为什么做错了？              → 01
边界、职责或 owner 错了？   → 02
流程、状态或生命周期错了？  → 03
模块交互规则错了？          → 04
失败处理错了？              → 05
取舍理由或机制变了？        → 06
证明方式错了？              → 07
实施顺序或范围错了？        → 08
局部私有实现错了？          → Code / 当前 Task
```

定位后从该层向下检查实际影响，不机械重写全部文档。

## 5. 宣布 Done 前

- [ ] Goal 已实现，而不只是代码已提交。
- [ ] 必需 Verify 在当前基线实际通过。
- [ ] Must not、依赖方向和修改范围已经检查。
- [ ] 未运行检查的原因和影响已说明。
- [ ] 没有影响当前完成范围的未解决 Design Delta。
- [ ] Accepted Decision 已传播到受影响的规范。
- [ ] 规定的 Completion Review 已接受。
- [ ] Current Facts 已刷新，完成 Task 已压缩。

## 6. 评审外部建议或 AI 输出

- [ ] 先读 Objective、Blocker、Design Delta 和结论。
- [ ] 抽查决定链中最关键的事实证据。
- [ ] 独立比较候选方案、代价、可逆性和影响范围。
- [ ] 区分 Accept、Reject、Explicitly Deferred 和 Needs Evidence。
- [ ] 区分决定接受、规范传播、实现完成和验证通过。
- [ ] 只把已核实、可抽象且去除可识别信息的原则放回知识库。
