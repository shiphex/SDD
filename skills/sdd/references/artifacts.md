# 产物与输出

沿用目标项目已有的规范位置和命名。缺少约定时，优先用一份短说明合并必要信息；内容增长或读者不同后再拆分。

## Spec

最小 Spec 回答：

- 问题、目标、非目标和成功标准是什么？
- 当前事实与目标之间缺少什么？
- 哪些边界、契约和失败语义必须成立？
- 哪些内容已经决定，哪些仍待裁决？
- 用什么实际证据验收？

不要把未经核实的实现描述为事实，也不要提前固定不影响契约的私有细节。

## 决定

重要决定记录背景、证据、候选方案、取舍、状态、影响位置和验证方式。延期项记录重审条件及依赖它的工作。

决定接受后，分别追踪：

- 规范是否更新。
- 实现是否落实。
- 验证是否覆盖。
- 当前任务是否仍具备执行条件。

## 任务

近期任务包含一个主要可验证结果、引用依据、前置条件、允许范围、必要约束和验收方式。禁止事项用于防止最可能发生的范围扩张，不罗列无关领域。

## 完成记录

完成记录包含：

- 实际完成的结果和修改范围。
- 已执行检查、观察结果及适用版本。
- 每项成功标准对应的证据。
- 未验证限制、独立延期事项和后续工作。

证据不足时使用“进行中”“部分完成”或项目已有等价状态，不用措辞掩盖缺口。

## 评审输出

先给结论及影响，再列证据、待决问题和可推进范围。只评审时不直接修改被评审产物，除非用户同时要求修订。

## 内容输出

内容任务可以使用虚构 Spec、伪代码、对话和图示文字。明确标注教学推演，不创建可运行项目，也不声称案例已经通过实际测试。
