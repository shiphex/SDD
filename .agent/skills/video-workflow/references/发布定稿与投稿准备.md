# 发布定稿与投稿准备

在用户要求将完整预览定稿、去除预览状态文字或准备平台投稿材料时读取。沿用当前 run 和既有授权，保留旧版；新版本放在该 run 的独立发布目录。实际录音、转写、对齐、剪辑映射、审核记录与媒体始终留在 Git 忽略目录。

## 确认基线与接受范围

先核对工作流中的阶段、当前产物、依赖哈希和用户反馈。用户明确接受当前内容与听感，或批准明确写明接受现状的计划，可将相应问题登记为 `accepted` 并保留决定；单独“大致满意”或要求制作预览不自动构成验收。记录接受的具体版本及剩余改动范围，不要求再次批准已经接受的细节。

质量记录分别说明用户反馈、自动检查、画面查看和逐段人耳听审。用户接受现有听感不表示本轮另做了逐段听审；自动检查结果也不能替代接受记录。

## 清理画面与复用音轨

- 检查全部独立页面和展开状态，包括继承早期版本的图片、页脚、结尾、封面及公开文案。页面 ID 和生成目录不能证明素材已经清洁。
- 从页面绘制代码或源素材移除预览状态文字，保留用户要求的定位、虚构标记和证据说明。生成器已有模式参数时使用发布模式；不要为清标记覆盖原素材或裁掉有效内容。
- 仅修改画面且最终 WAV 的 SHA256 与已核对基线一致时，复用转写、强制对齐、SRT 和章节时间，不重新识别。检查字幕及对齐的依赖仍有效；若音轨有任何变化，返回定稿转写与对齐流程。
- 从与该 WAV 对应、已经接受且哈希有效的基线 MP4 复制 AAC，替换视频画面。工具校验 WAV 相同、时长及 AAC 包载荷；基线视频与 WAV 的对应关系和接受状态仍需从工作流记录核对。
- 小范围视觉修改可比较新旧素材像素，确认差异限于批准区域。随后从最终 MP4 提取每个独立状态的实际帧，检查继承素材和结尾；不能只检查生成代码或少数页面。

`scripts/release_tools.py reuse-audio` 将已有的新画面视频与已接受视频的 AAC 合并，丢弃源元数据和章节，启用 faststart；不改变字幕或剪辑时间。输入包括新画面 MP4、基线 MP4、最终 WAV、基线 WAV 和新输出路径；拒绝 WAV 哈希变化、时长不符、非 AAC 基线及覆盖已有文件。该命令只合成媒体，不批准内容或听感。

```powershell
$release = '.agent/skills/video-workflow/scripts/release_tools.py'
$runDir = '.local/video/lesson-01'
python $release reuse-audio --video "$runDir/release/visual.mp4" --baseline-video "$runDir/accepted/video.mp4" --audio "$runDir/release/final.wav" --baseline-audio "$runDir/accepted/final.wav" --output "$runDir/release/video.mp4" |
    Set-Content -Encoding UTF8 "$runDir/release/audio-reuse-check.json"
```

检查命令退出码和 JSON 结果，工具失败时不登记成功产物。原视频不是 AAC 或需要改变音轨时不使用此入口，按既有合成与验证流程导出，并记录实际音频处理。

## 投稿材料与公开包

平台已明确时准备相应标题、简介、标签、封面和章节文案；无法从上下文确定且会影响材料时再询问。保持既有定位，标明虚构案例和计划中的测试，不补写效果承诺、实际验证结果或用户身份。

平台尺寸、格式、分类和字数等约束在临近投稿时按官方入口或文档核对。界面无法读取时，明确封面尺寸等是制作约定，上传以实际界面为准；不把一次投稿采用的尺寸写成永久平台要求。封面比例与排版可按平台需要调整，无需让所有任务生成固定数量的封面。

将允许公开的最终文件逐项列入清单。视频、经核对的独立字幕、选用封面和投稿文案通常适合公开；章节时间表或页面总览按用户需要选择。原录音、内部转写、对齐 JSON、工程、映射、问题记录、来源索引及本机路径不因位于同一目录而进入公开包。

`package-public` 只打包清单列出的相对路径和 SHA256，保留相对子目录；清单根目录为清单文件所在目录。清单留在内部，无需随 ZIP 公开。

```json
{
  "files": [
    {"path": "video.mp4", "sha256": "<最终视频的 SHA256>"},
    {"path": "video.srt", "sha256": "<已核对字幕的 SHA256>"},
    {"path": "cover.jpg", "sha256": "<选用封面的 SHA256>"},
    {"path": "submission.md", "sha256": "<公开投稿文案的 SHA256>"}
  ]
}
```

```powershell
python $release package-public --manifest "$runDir/release/public-files.json" --output "$runDir/release/submission.zip" |
    Set-Content -Encoding UTF8 "$runDir/release/package-check.json"
```

清单生成前检查文件的公开范围、隐私、语言、来源和链接。工具拒绝空清单、缺失或变化的哈希、重复归档路径、绝对路径、目录穿越及解析后越出清单目录的路径；核对实际 ZIP 内容及文件哈希。工具不会判断文件内容是否适合公开，不递归加入目录，也不登录或上传。

## 登记与交付

保留已有样片验收与全片编辑授权。先登记本轮最终大纲和用户接受记录，再更新问题状态并批准当前内容；按现有 `register-sample-output.ps1 -Scope full -Action audio/delivery` 或对应全片入口登记正式音轨和交付。音轨没有变化时，登记复用的已核对转写与对齐；不要为了经过阶段再次运行模型。

已交付视频使用的项目方案或内容参考文档，可在更新其状态说明之前用 `workflow-state.ps1 -Action snapshot-reference -RunId <run-id> -ArtifactId <参考资料 ID> -Path <当前 run 内的新快照路径>` 固化当时接受的版本。入口只接受已登记、当前且被批准 gate 直接引用的 `project-plan` 或 `content-source-*` 文本文档；验证源与副本哈希相同，保留出处与时间，既有接受结论不变。它不处理媒体或审批记录，也不批准新资料。后续视频内容使用新的参考文档时重新登记来源，相关产物与审批按原规则失效并复审。

沿用现有依赖关系：素材或时间线变化使视频过期，音轨变化使字幕、对齐和视频过期。另登记投稿文案、封面、公开清单和 ZIP；ZIP 依赖公开清单及其中每个文件。基线与当前输出使用不同产物，避免依赖当前输出自身。

内容已接受、正式交付与检查产物均为 current，公开包校验通过后，可用状态助手的 `full_release_ready` gate 登记“发布版，可投稿”，依赖当前接受记录、MP4、SRT、质量记录、自动检查和公开包。它与 `full_quality_review` 阶段并存，不代表平台上传或处理完成。

交付成片、独立字幕、投稿包以及需要的章节和页面总览；内部修订与质量记录另列。状态明确区分内部预览、可投稿、已上传和已发布。准备材料不授权外部动作；只有用户明确授权实际上传或发布且工具可用时才执行，并据实际结果记录状态及平台链接。登录失败、响应丢失或平台结果未知时如实保留未知，先查询已有结果再考虑重试。

Windows PowerShell 5.1 中含中文字符串的 `.ps1` 使用 UTF-8 BOM；JSON 和 Markdown 使用工具能读取的 UTF-8。隐私模式检查应识别真正的本机路径，避免把 `https://` 中的字符误判为盘符路径；模式检查之外仍查看实际画面与文案。
